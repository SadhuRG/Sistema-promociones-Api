------------------------------------------------------------------------------
1. STACK Y CONEXIÓN
------------------------------------------------------------------------------
- Framework: FastAPI
- ORM: SQLAlchemy (síncrono)
- BD: PostgreSQL en Supabase
- Auth: JWT de Supabase Auth (validación con JWKS)
- Storage: Supabase Storage (cliente oficial supabase-py)
- Config: pydantic-settings (.env)
- Prefijo API: /api/v1
- Docs: http://127.0.0.1:8000/docs

Variables de entorno (.env):
  - DATABASE_URL
  - SUPABASE_URL
  - SUPABASE_JWKS_URL
  - SUPABASE_KEY              (Anon Key o Service Role Key)
  - SUPABASE_STORAGE_BUCKET   (default: flyers)

Cómo levantar:
  uvicorn app.main:app --reload

Cómo correr seeder:
  python -m app.db.seeder

3. BASE DE DATOS (SUPABASE) - TABLAS
------------------------------------------------------------------------------
Tablas principales:
  - especialidades
  - users                 (vinculada a auth.users por id_user_supabase UUID)
  - doctores
  - promociones
  - informes
  - horario

Tablas intermedias (many-to-many):
  - doctor_especialidad
  - promocion_especialidad
  - informe_especialidad

Roles en users:
  - User (por defecto al registrarse vía trigger de Supabase)
  - Admin (se asigna manualmente en BD)

Estados comunes:
  - Activo / Inactivo

Storage:
  - Bucket público: flyers
  - Carpetas lógicas: promociones/, informes/

6. SEGURIDAD Y STORAGE
------------------------------------------------------------------------------
Archivo: app/core/security.py
  - get_current_user       -> valida JWT + busca en users + estado Activo
  - get_current_admin_user -> exige rol Admin (403 si no)

Archivo: app/core/storage.py
  - upload_image_to_supabase(file, folder) -> URL pública
  - Extensiones: .jpg .jpeg .png .gif .webp .svg
  - Nombre único con UUID

Header en rutas protegidas:
  Authorization: Bearer <access_token_supabase>


------------------------------------------------------------------------------
7. ENDPOINTS
------------------------------------------------------------------------------

[PÚBLICOS]
  GET  /
  GET  /api/v1/especialidades/
  GET  /api/v1/especialidades/{id}
  GET  /api/v1/doctores/                         (?estado, ?especialidad_id)
  GET  /api/v1/doctores/{id}
  GET  /api/v1/promociones/                      (?especialidad_id, ?estado, ?titulo)
  GET  /api/v1/promociones/{id}
  GET  /api/v1/horarios/                         (?id_doctor, ?estado)
  GET  /api/v1/horarios/{id}
  GET  /api/v1/informes/                         (?especialidad_id, ?titulo)
  GET  /api/v1/informes/{id}

[AUTENTICADOS - JWT]
  GET  /api/v1/auth/me

[SOLO ADMIN]
  POST/PUT/DELETE  /api/v1/especialidades/...
  POST/PUT/DELETE  /api/v1/doctores/...
  POST/PUT/DELETE  /api/v1/promociones/...       (multipart: imagen opcional)
  POST/PUT/DELETE  /api/v1/horarios/...
  POST/PUT/DELETE  /api/v1/informes/...          (multipart: imagen opcional)

Notas multipart (promociones / informes):
  - Content-Type: multipart/form-data
  - Campo archivo: imagen
  - especialidad_ids: "1,2,3" o "[1,2,3]"

8. PERMISOS POR RECURSO
------------------------------------------------------------------------------
Recurso          | GET | POST | PUT | DELETE
-----------------+-----+------+-----+--------
Especialidades   | Pub | Adm  | Adm |  Adm
Doctores         | Pub | Adm  | Adm |  Adm
Promociones      | Pub | Adm  | Adm |  Adm
Horarios         | Pub | Adm  | Adm |  Adm
Informes         | Pub | Adm  | Adm |  Adm
Auth /me         | Aut |  -   |  -  |   -

Leyenda: Pub = Público | Aut = JWT | Adm = Admin
